Phase 2: scriptable command surface (-WhatIf, -Json, non-interactive)

Adds src/Wuu.Command.psm1 plus command mode in the bootstrap, so WUU runs unattended:

    WUU.ps1 check -All
    WUU.ps1 show available -Computer SRV01 -Json
    WUU.ps1 install -Computer SRV01 -WhatIf
    WUU.ps1 -Help

DESIGN: dispatch, not duplicate
The command layer reimplements nothing. Each verb resolves its arguments into (a) an action name
and (b) the ordered answers the interactive helper would have prompted for, then calls the SAME
$consoleActions handler the menu calls. There is therefore exactly one implementation of every
operation. Consequences, all intentional:
  - `-Computer` is just the first answer to the handler's selection prompt, so names / comma
    lists / prefixes / "all" all work with no per-verb selection logic.
  - A verb missing required input FAILS with a clear message instead of prompting.

New in src/Wuu.Console.psm1: a single input choke point (Initialize-WuuInputMode / Read-WuuAnswer).
Read-WuuSelection, Read-WuuYesNo and the handler prompts now route through it, which is what
makes the handlers scriptable without knowing they are scripted. Interactive prompting is the
default and behaviour is unchanged when no verb is given.

-WhatIf short-circuits mutating verbs BEFORE any handler runs (download/install/restart/service),
so no payload is queued and no remote state is touched.

Command mode also loads the saved computer list first when one exists - otherwise `-All` would
run against an empty store and silently do nothing - then drains the job scheduler for a bounded
period so the operation it started actually makes progress before the report. Exit code is 0/1 so
a script or CI can branch on it.

Bugs found while building this (each caught by a check, none by inspection)
1. The release validator found the verb table pointing at EventViewUpdateLog, which had NO
   $consoleActions handler - and the menu had the same gap (no key bound to it), so nothing had
   noticed the operation was unreachable. Added the adapter and a `g` menu key.
2. `Unknown = @()` in a hashtable literal is a FIXED-SIZE array; the first unrecognised option
   threw "Collection was of a fixed size" - i.e. the unknown-option reporter crashed precisely on
   the input it exists to report. Now an ArrayList.
3. `service restart` did not parse: 'service' was missing from the subverb-verb list.
4. Two test-expectation errors (a closure that rebound $script:called, and a mutating-verb count
   asserted as >4 when the correct set is exactly 4). Fixed by capturing the list by reference
   and by asserting the SET rather than a count.
5. The UTF-8 BOM bug recurred twice more, on Wuu.Command.psm1 and Package-WUU2.ps1. Rather than
   rely on memory a fourth time, the validator now GATES it: every file containing non-ASCII bytes
   must carry a BOM (8th check). It found Package-WUU2.ps1 immediately after being written.
